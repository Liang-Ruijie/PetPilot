# 前端适配声明

> 阶段 3-0 产出 · 2026-11-04 · 产品：PetPilot

## 1. 项目判断

- **产品类型**：猫主人 Personal Agent（对话式记录 / 分猫归档 / 纠错 / 提醒 / 就医摘要 / 周回顾）。
- **主要用户**：猫主人，单人使用（合成体验空间，固定验证码登录）。
- **主要终端**：桌面 Web + 移动 Web（手机浏览器可用）。
- **新项目或已有项目**：新前端工程；后端 FastAPI 已就绪，前端从零建。
- **本阶段业务目标**：把已验证的后端能力做成正式的主人端对话界面，替换阶段 2 的临时验收页。

## 2. 输入资料

- PRD：已读取（一页纸MVP.md 等 3 份）。
- 技术适配声明与决策台账：已读取（D1–D10 均已定）。
- 阶段 2 界面类型：**临时验收界面（本阶段废弃，删除 backend/static/index.html 入口）**。
- 接口文档：完整（后端已实现，路由见 backend/app/api/）。
- 设计稿：无（产品经理未提供，先按中性方案做一版代表页）。
- 现有代码：后端 FastAPI + SQLite 已就绪，repository 层数据契约不变。

## 3. 技术选择

- **框架与版本**：React + Vite + TypeScript（严格模式）。**偏离手册默认 Next.js**，原因见第 6 节；版本取建项目时稳定版。
- **样式与组件策略**：Tailwind CSS + CSS 语义变量（B 层默认）；图标 Lucide（B 层默认）。
- **数据请求与状态策略**：集中式 API 层（`src/api/` 统一封装 fetch + token）；对话流为同步提交，状态简单，先不引入 TanStack Query / Zustand（无真实复杂度）。
- **流式通信策略**：本阶段后端对话是"提交→同步返回"，不接 SSE；如后续要流式展示再引入（记录为暂缓项）。
- **表单方案**：原生受控表单（简单输入，不引入 React Hook Form + Zod）。
- **测试方案**：Vitest + React Testing Library（B 层默认）。
- **部署环境**：本机 `vite dev` 开发 + `vite build` 生产构建（D10 本轮不上线）。

## 4. Agent 状态

- **后端状态 → 前端统一状态映射**：
  - 对话消息：`idle / submitting / success / error`；
  - 提醒：`pending / done / cancelled / paused` + 派生 `is_due`（到期）；
  - 各列表（事实/提醒/摘要/照片/周回顾）：`loading / empty / error / ready` 四种分开展示。
- **等待用户确认方式**：多猫归属歧义 → 展示"归属未知"挂起片段（补归属为二期，本阶段只展示）。
- **取消、重试、断线恢复方式**：提交失败显示统一错误 + 可重发；登录失效自动清 token 回登录页。
- **任务 ID 和恢复入口**：无长任务（均为同步请求），无需任务恢复入口。

## 5. 页面与产物

- **核心页面**：登录页；主人端单页对话工作台（输入框 + 宠物管理 + 记录/纠错/提醒/摘要/照片/周回顾各视图）。
- **核心业务闭环**：登录 → 发消息（记录/纠错/提醒/摘要）→ 看回执 → 查各列表 → 上传照片 → 生成周回顾。
- **产物类型和预览方式**：文本（回执、叙述性摘要、周回顾）直接展示；照片展示文件名 + 描述（不渲染原图预览，保持"只存原图"语义）。
- **响应式目标**：桌面端 + 移动端（≤390px 起）基本布局可用。

## 6. 偏离本手册的地方

| 偏离项 | 原因 | 影响 |
| --- | --- | --- |
| 框架用 React + Vite，不用 Next.js | PRD §7 明确指定"React + Vite + TS"；产品是单页对话应用，无服务端渲染/多页面路由需求 | 无业务影响；少了 SSR 能力（本产品不需要） |
| 不接 SSE | 后端对话为同步提交返回（后端未做流式） | 无流式打字机效果；后续需要再引入 |
| 不引入 TanStack Query / Zustand | 单页对话流状态简单，无多页面共享缓存 | 无 |
