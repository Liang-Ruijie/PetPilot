# 第 3-1 阶段开发文档（前端）

> 配套：`docs/阶段文档/前端适配声明.md`、`docs/设计参考/PetPilot-DESIGN.md`、前端技术栈手册。
> 本阶段只做"可运行骨架 + 代表页"，先让产品经理看视觉方向，确认后再铺开全部页面。

## 1. 本阶段目标

用户打开网页，能看到一个符合 DESIGN.md 风格的"PetPilot 主人端对话工作台"代表页，并判断视觉方向是否满意。

## 2. 范围

### 本阶段包含
- 工程骨架：Vite + React + TypeScript（strict）+ Tailwind CSS + Lucide 图标；
- 设计变量：把 DESIGN.md 的配色/字体/圆角/阴影/间距落地成 Tailwind `@theme` tokens；
- 代表页：登录页 + 主人端主对话工作台（顶部品牌与宠物列表、中部消息流、底部输入框）；
- 基础 API 客户端骨架（登录用真接口，消息流先用示例数据演示视觉）。

### 本阶段不包含
- 全部页面的完整后端对接（纠错/提醒/摘要/照片/周回顾的完整交互在后续子阶段）；
- 移动端精细适配（代表页先保证基本可用，验收时再打磨）；
- 流式输出、取消/重试等 Agent 高级交互。

## 3. 用户流程

打开 → 登录（固定验证码）→ 看到对话工作台 → 底部输入一句话 → 看到回执气泡 → 点"查记录/查提醒"等切换视图（本阶段先摆出入口，交互后续补）。

## 4. 页面状态矩阵

| 状态 | 登录页 | 对话工作台 |
| --- | --- | --- |
| 加载中 loading | 登录按钮 loading | 消息提交 loading |
| 空 empty | N/A | 无消息时展示引导文案 |
| 成功 success | 跳转 | 显示回执气泡 |
| 失败 error | 验证码错误提示 | 提交失败提示 + 可重发 |
| 等待确认 | N/A | N/A（本阶段无） |
| 断线恢复 | N/A | 登录失效自动回登录页 |

## 5. 接口契约

- 登录：`POST /api/auth/login`（真接口，其余先静态）；
- 复用后端统一错误结构 `{"error":{"code","message"}}`。

## 6. 实现方案

- 目录：`frontend/src/`（`api/`、`components/`、`pages/`、`styles/`）；
- 设计变量用 Tailwind v4 `@theme` 定义，集中一处可改全站；
- 代表页单文件组件起步，确认风格后再拆正式组件结构。

## 7. 验收标准

- 一条命令起前端（`npm run dev`）；
- 桌面与移动端宽度布局基本正确；
- 视觉符合 DESIGN.md（冷灰画布、白卡片、近黑文字、蓝色点缀、18px 圆角、系统字体）；
- 产品经理看代表页确认方向。

## 8. 风险与回退

- 风险：产品经理对代表页风格不满意 → 只改设计变量与代表页，不涉及后端；
- 回退：前端独立工程，可整体推倒重做，不影响已验收的后端。

## 9. 交付结果

- 可运行的 Vite 前端工程 + 代表页（登录页 + 对话工作台）；
- 设计变量 tokens 落地；
- 代表页截图放入证据包。
