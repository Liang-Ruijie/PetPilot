# 记忆承接设计说明

> 阶段 3 收尾前的一次小范围增强 · 2026-11-06 · 产品：PetPilot（宠物合伙人 MVP）
> 目标：解决"上一轮刚问过，下一轮短答却接不上"（如：助理问"需要整理就医摘要吗"→ 用户答"需要"→ 却被当成一句新话）。
> 本文档只描述"最小必要的记忆承接"，**不是完整记忆系统**，不引入向量库 / Embedding / 知识图谱 / 多 Agent / 新框架。

## 1. 问题与根因

**现象**：短答接不上。例如

1. 助理："需要我整理就医摘要吗？" → 用户："需要" → 系统又问"是哪只猫？"（应该直接整理那只猫的摘要）
2. 助理："请问是整理哪只猫的摘要？" → 用户："明月" → 系统却回"档案能看到，想记录点什么？"（应该继续生成明月摘要）

**根因**：后端每次调用模型时，只传「当前这句话 + 宠物身份 + 最近事实 + 待归属片段」，**不传历史对话**。模型看不到自己上一轮问过什么，于是把"需要""明月"这类短答当成一句孤立的新话，流程就断了。

## 2. 方案（最小改动，只动后端）

1. **喂历史**：每次调用模型时，把最近几轮用户与助理的问答（按时间顺序）一起传入，让模型能接上指代。历史只用于"理解承接"，不作为新的执行授权。
2. **分猫读事实**：给模型看的"最近事实"，当前猫能确定时优先给这只猫，多猫时分别保留，总量仍设上限，避免某只猫的新记录挤掉另一只猫。
3. **care 校验最小适配**：就医摘要的归属校验，允许"模型给的猫有效 且（当前这句话提到了它 或 全账户只有这一只猫）"就接受；多猫且无法核实时仍追问，不瞎猜。
4. **prompt 加承接规则**：短答只承接唯一明确的待答事项；歧义就澄清；"好的/行"不批量批准动作。

## 3. 核心：规则 vs 记忆的分工（必须写清，防止误删）

模型加"记忆（上下文）"后，之前补的确定性规则**不是全部作废**。规则分两类：

| 类型 | 例子 | 记忆能替代吗 |
| --- | --- | --- |
| **A. 安全底线规则** | 防串猫（整词匹配、多猫歧义挂起）、防假保存（落库才回"已保存"）、防重复执行（"别提醒"不算授权）、纠错版本校验（expected_version）、提醒缺时间就追问、quote 必须落在原文 | **不能，永远保留**。模型有记忆也会偶尔犯错，必须由代码兜底 |
| **B. 猜意图补丁** | 在文字里找"整理"就猜要摘要、找"建好"就猜建好猫了、找"发送"就触发模拟回复 | **部分被记忆取代**，但建议保留作兜底（模型偶尔理解错时仍能救） |

**结论：记忆负责"听懂你"，规则负责"保证不出错"，两者是分工，不是谁取代谁。** 任何阶段都不允许以"有记忆了"为由删除 A 类安全规则。

## 4. 历史的使用边界（防越权）

- 历史只用于**理解指代和承接**，不能作为新的执行授权：过去说过"明天提醒我"，不能因为出现在历史里就再次建提醒。
- 历史中的助理回答，不能自动变成主人的事实或医学依据。
- 历史有长度上限（合计约 6000 字符），超限从最早的完整轮次开始裁剪，保留最近内容；**不额外调用模型生成历史摘要**。
- 当前消息不能重复放入历史。

## 5. 本轮明确不做

- 不新增"对话状态表 / 记事本"（短答承接靠历史 + prompt 规则，不靠状态表）。
- 不做"历史记录检索 / 补查返回有效版本"（超出 MVP 功能范围）。
- 不新增"总结记忆 / 反思记忆"的模型调用（避免每条消息多一次模型调用、成本翻倍）。
- 正常一条消息仍走现有处理链路；已有成功结果不因历史重复执行。

## 6. 已知限制（如实声明）

- **"暂停状态"不长期保留**：用户说"先不问了"这类暂停，是靠历史对话记住的；一旦历史被后续聊天挤到 6000 字上限之外，暂停就可能"失忆"。**本方案不承诺永久记住暂停，也不承诺任意久远问题都能自动找回。**

## 7. 验收场景（少量多轮，不只验 JSON 提取）

1. 提议摘要 → "需要" → 追问猫 → "明月" → 生成正确摘要，不新增虚假观察；
2. 多猫歧义：短答无法确定是哪只猫时，澄清，不串猫；
3. 原事实更正后，后续读取有效版本，历史不把旧值写回；
4. 提醒创建后继续聊天/刷新，不重复创建；取消后不因旧消息自动恢复；
5. 用户"不知道/先不问了"后，下一轮不重复追问；
6. 刷新或服务重启后，必要待答仍能承接（历史持久化在 SQLite，天然满足，顺带验证）。

## 8. 改动文件清单（写代码时）

- `backend/app/services/model_client.py`：`_build_user` / `extract` 加历史参数；`SYSTEM_PROMPT` 加承接规则与"历史仅供理解指代"边界。
- `backend/app/api/messages.py`：取最近消息历史（在保存当前消息之前）；facts 按猫分组；care 校验最小适配。
- 前端：**零改动**。
