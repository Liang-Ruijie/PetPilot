## 3. 上线前必须做的代码改造（这是主要工作量）

当前是"本机版"，离上线还差这几块：

| 改造项 | 现状 | 要改成 |
| --- | --- | --- |
| 数据层 | SQLite + SQLAlchemy 直连（约 84 处 db 操作） | 切到平台 PostgreSQL 网关（`DATA_BACKEND=cloudbase_rest`，走 HTTPS REST） |
| 登录 | 固定验证码 123456 | 邀请码登录（一人一码、码即身份） |
| 数据隔离 | 无（所有人共享一份数据） | 按用户隔离，只能看自己的数据 |
| 账号方案 | 无 | 你的空间（清空按钮）+ 面试官空间（预置演示数据 + 每次登录重置 + token 4 小时失效） |
| 安全 | 无 | 登录失败限流（5 次锁 15 分钟）、每人每日模型调用上限 |
| 前端部署 | Vite 静态，开发时靠 dev proxy | 生产环境 `/api` 转发（nginx 或等价方式），登录 Cookie 同域 |
| 打包 | 无 Dockerfile | 后端 + 前端各一个 Dockerfile / .dockerignore |

## 4. 部署步骤（改造完成后）

1. 建表（PostgreSQL 迁移 SQL，开 RLS 不建策略）；
2. 首次部署后端（预期先因缺配置启动失败，属正常）；
3. 写入线上环境变量（0.25 核 / 0.5 GB / 0～1 实例，密钥不上命令行）；
4. 部署前端、写转发配置；
5. 外网验证（登录、生成、历史、隔离、限流、重新发布后数据仍在）。
