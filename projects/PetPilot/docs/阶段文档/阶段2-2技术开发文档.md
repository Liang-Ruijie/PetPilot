# 第 2-2 阶段技术开发文档｜纠错 + 提醒 + 就医摘要 + 照片

> 配套文档：`docs/PRD/一页纸MVP.md`（以它为准）、`docs/PRD/宠物合伙人_MVP规则映射与提示词.md`、通用技术栈手册。
> 本文档只覆盖阶段 2-2。AI 开发时不得提前实现其他阶段的能力（周回顾、语音、删除、真实上线等不做）。

## 一、阶段目标

- **交付范围**：在 2-1 地基上补齐核心闭环的剩余 4 项——①纠错（带版本+来源）②提醒（授权裁决+到期+暂停/取消/完成）③就医摘要（只生成不外发）+ 模拟医院回复 ④照片上传（只存原图+描述）。
- **阶段产物**：扩展后的 FastAPI 后端；临时验收界面增加纠错/提醒/摘要/照片入口；mock 测试全过；`restart-check.sh` 扩展到覆盖新表。
- **验收标准**（对齐 PRD §9 的 2/4 条）：
  1. 纠错能更新同一条事实、保留版本与来源，不新增一条让旧值仍影响结论；
  2. 提醒：明确指令才建，"别提醒/如果…/医生说"不建；到期能出现；可暂停/取消/反馈完成；重启后仍在；
  3. 就医摘要只生成、可核对，点"模拟医院回复"看到一条明确标注模拟的回复；
  4. 照片只存原图+描述、归属某只猫，无 OCR/识别。
- **明确不做**：周回顾（2-3）、语音转文字（阶段3前端）、短信/OCR/云端ASR/COS、删除能力、真实外发/找医院（二期）。
- **本阶段打通的主链路片段**：登录 → 发文字（含纠错/提醒/摘要意图）→ 服务端裁决 → 落库 → 回执；外加照片上传链路。

## 二、技术适配摘要

- 延续《技术适配声明》结论：后端先行 + 临时验收界面，FastAPI + SQLite + DeepSeek。
- 本阶段新增按需模块：本地文件目录存照片（无 COS）；持久化任务记录（提醒，单进程，不引入任务队列）。
- 本阶段偏离/暂缓：提醒"到期"不用后台调度器，改为查询时按 `due_at` 判断是否到期（MVP 单用户演示足够；引入调度器是二期）。

## 三、技术栈与模型

- 复用 2-1 全部组件；新增 `python-multipart`（照片 multipart 上传）。
- 模型：DeepSeek `deepseek-chat`。主链路一个模型调用同时输出 `operations`（含 `correct_fact`）与 `dialogue`（含 `reminders`、`care_requests`）；就医摘要正文再用一次模型调用生成叙述性摘要。

## 六、数据、资产与状态

- 持久化：SQLite；照片存 `data/uploads/`（gitignore 已覆盖 `data/`），元数据入表。
- 新增表（002 迁移）：

| 表 | 字段 | 说明 |
| --- | --- | --- |
| corrections | id、fact_id(FK)、old_value、new_value、old_topic、new_topic、quote、source_message_id(FK)、created_at | 纠错历史，保证版本可追溯 |
| reminders | id、pet_id(FK可空)、quote、due_at、status、created_at | 提醒；status=pending/done/cancelled/paused |
| care_summaries | id、pet_id(FK)、title、fact_ids(JSON)、summary、source_message_id(FK)、created_at | 就医准备摘要（只生成不外发） |
| photos | id、pet_id(FK可空，上传时选猫)、filename、stored_path、description、message_id(FK)、created_at | 照片只存原图+主人描述，归属某只猫 |

- 状态机：`reminders.status`：pending → done/cancelled/paused；`facts.version`：纠错时递增；`held_segments.status` 仍 pending（补归属二期）。

## 七、API 设计

| 方法 | 路径 | 说明 | 关键错误码 |
| --- | --- | --- | --- |
| POST | /api/messages | 扩展：响应新增 corrections、reminders、care_requests 结果 | FACT_VERSION_CONFLICT |
| GET | /api/reminders | 列出提醒（含是否到期） | — |
| POST | /api/reminders/{id}/complete | 反馈完成 | REMINDER_NOT_FOUND |
| POST | /api/reminders/{id}/cancel | 取消 | REMINDER_NOT_FOUND |
| POST | /api/reminders/{id}/pause | 暂停 | REMINDER_NOT_FOUND |
| POST | /api/photos | multipart 上传（file + pet_id + description） | FILE_TOO_LARGE / FILE_TYPE_INVALID |
| GET | /api/photos | 列出照片 | — |
| GET | /api/care-summaries | 列出就医摘要 | — |
| POST | /api/care-summaries/{id}/simulate-reply | 返回明确标注"模拟"的医院回复 | CARE_NOT_FOUND |

- **纠错**：模型输出 `correct_fact(fact_id, expected_version, 新值)` → 服务端校验 fact 存在且 version==expected_version，更新值并 version+1，写 corrections 历史；版本不符返回 `FACT_VERSION_CONFLICT`（不静默覆盖）。
- **提醒授权裁决（服务端，不交给模型）**：`reminder_intent` 正则——否定（别/不要/不用/取消提醒）、假设（如果/假如/要是）、问句（吗/？）、引用（医生说/他说）→ 不建提醒；只有明确指令才建。quote 必须完整落在原文。
- **时间解析**：支持"今天/明天/后天 + 上午/下午/晚上 + X点/X点半"等常见表达；解析不出时间 → 提醒建为 pending 并追问，不擅自加默认时间。
- **照片**：校验格式（jpg/png/webp）、真实类型、大小（≤5MB）、安全文件名；存 `data/uploads/`。

## 八、Prompt 设计

- 在 2-1 系统提示词基础上，补回 `correct_fact`（必填 fact_id + expected_version + quote 从猫名起连续引用到新值）、`dialogue.reminders`（仅主人明确交代的提醒，quote 完整子句，不含否定/引用/假设/问句）、`dialogue.care_requests`（只整理内部摘要，不发送不选医院）。
- 就医摘要正文：单独一个"汇总这些事实为就医摘要"的模型调用，输入为选中事实列表，输出叙述性摘要；红线仍是不诊断、不处方。
- 模型输出仍经 Pydantic 强校验 + 宽容解析（缺 kind 默认 add_observation 等 2-1 结论延续）。

## 九、验收界面

- 临时验收界面扩展：聊天框旁加"纠错/提醒/摘要"自然语言即发；加"上传照片"按钮；加"提醒"与"就医摘要"两个查看区；"模拟医院回复"按钮明确标注模拟。

## 十、测试要求

- 第一层 mock（pytest）：
  1. 纠错：更新同一条 fact、version+1、写 corrections；expected_version 不符 → FACT_VERSION_CONFLICT 且不改动；
  2. 提醒授权："明天上午九点提醒我给明月称重"→建（due_at=明天9点）；"别提醒我称重"/"如果明天…"/"医生说提醒"→不建；
  3. 提醒操作：完成/取消/暂停状态流转；重启后仍在；
  4. 就医摘要：生成摘要（mock 模型）且 fact_ids 只含本猫事实；模拟回复明确标注"模拟"；
  5. 照片：合法图片入库；非图片/超大/伪造扩展名 → 拒绝；
  6. 回归 2-1 全部用例不破坏。
- 第二层真实冒烟：真实 DeepSeek 走通"纠错一条→版本+1"、"设提醒→到期出现"、"整理就医摘要→看到摘要"、"上传照片→原图+描述"。
- `restart-check.sh`：扩展为写入提醒后重启读回。

## 十一、验收清单（产品经理照着点）

- [ ] 发"刚才明月是 40 克，不是 20 克" → 同一条记录更新为 40、版本+1（不是多出一条）；
- [ ] 发"明天上午九点提醒我给明月称重" → 提醒列表出现"明天 09:00 给明月称重"；
- [ ] 发"别提醒我称重" → 不建提醒；
- [ ] 到点后提醒显示"已到期"，可点"完成/取消/暂停"；
- [ ] 发"帮我整理贝塔的就医摘要，先不要发" → 看到摘要（只生成）；点"模拟医院回复" → 看到明确标注模拟的回复；
- [ ] 上传一张照片+一句描述 → 照片列表出现原图+描述，无识别结果；
- [ ] 重启后端再刷新 → 提醒、照片、摘要、纠错记录都还在。
