# 技术适配声明

> 阶段 1 产出 · 2026-11-04 · 产品：PetPilot（宠物合伙人 MVP）

## 1. 产品形态判断

- **产品类型与核心任务**：猫主人的 Personal Agent。主人用一句话/照片/语音记录猫的日常，系统自动分猫归档、纠错带版本来源、设提醒、生成就医准备摘要。
- **核心交互**：多轮对话 + 分阶段确认（多猫归属歧义才问、纠错需回执、提醒授权由服务端裁决）。
- **开发路径**：后端先行。核心价值与风险都在后端 Agent 逻辑与"服务端裁决"（不串猫、纠错不改错、提醒不误执行），不是界面；先验证后端能力，再进正式前端。
- **验收界面**：临时验收界面（`backend/static/` 单个 HTML 聊天页，阶段 3 开始时废弃）。因为 Agent 产出是结构化 JSON，产品经理必须"打字 → 看分猫/回执"才能判断质量。
- **上线套餐**：免费体验版（台账 D9）。
- **当前阶段范围**：阶段 2 后端 MVP，从子阶段 2-1 开始（先做核心闭环）。

## 2. 采用的默认方案

| 方案 | 采用原因（一句话） |
| --- | --- |
| Python 3.12.x（本机已装 3.12.14） | 与上线镜像一致，无版本漂移 |
| FastAPI | 把能力做成可测试、可调用的 API |
| Pydantic | 校验接口入参与模型结构化输出（schema） |
| pytest | mock 自动化测试，verify.sh 第 2 项依赖 |
| Git | 已 init，密钥检查依赖仓库 |
| SQLite + SQLAlchemy + Alembic（1–2 个迁移） | 多实体关系（猫/消息/事实/提醒），PRD 指定不上 PG |
| DeepSeek 官方 SDK/兼容接口 | 台账 D4：国内模型、数据不出境、每月上限 100 元 |
| React + Vite + TS（阶段 3 用） | PRD §7 指定 |

## 3. 触发的按需模块

| 模块 | 触发条件 | 当前阶段是否引入 |
| --- | --- | --- |
| SSE 流式输出 | 对话产品需逐步展示模型生成过程 | 引入 |
| 本地文件目录存照片 | 照片只存原图 + 主人描述（无 OCR/COS） | 引入 |
| 持久化任务记录（提醒调度） | 提醒需跨重启保留、只执行一次 | 引入（单进程，不引入任务队列） |
| 浏览器语音识别（Web Speech API） | 语音转文字，失败回退文字输入 | 阶段 3 前端处理，后端不引入云端 ASR |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代/暂缓 | 原因 | 影响 | 何时重评 |
| --- | --- | --- | --- | --- |
| Web 前端默认 Next.js | PRD 指定 React + Vite + TS | 一页纸MVP §7 明确指定 | 无（同为 Web 端，阶段 3 实施） | PRD 变化时 |
| 阶段 4 默认上线腾讯云 | 本轮只本机演示，上线推迟下一轮 | 台账 D10 已定 | 本轮验收不含部署 | 真实模型验收通过后 |
| 云端 ASR / OCR / 短信 / COS | 本期全部不用 | 一页纸MVP §6 | 照片无 OCR、语音依赖浏览器 | 二期按需引入 |
| 删除能力 | 本期不做（聊天/整猫删除） | 一页纸MVP §5 | 纠错保留，无删除入口 | 二期 |

## 5. 强制底线检查

- **密钥与隐私**：通过。DeepSeek 国内模型，数据不出境、不用来训练；密钥进 `backend/.env`（.gitignore 已覆盖）。
- **数据与任务可恢复**：待处理。阶段 2 用 SQLite 持久化 + `scripts/restart-check.sh` 实际验证。
- **输入输出校验**：通过。Pydantic + 模型输出 schema 校验 + 服务端裁决（多猫归属/提醒授权/纠错版本不交给模型自由决定）。
- **错误与日志边界**：通过。统一 `{"error":{"code","message"}}`，不记密钥/密码/完整用户文档。
- **测试与真实模型验收**：mock pytest 全过 + 真实 DeepSeek 冒烟（无 Key 时记"待验"）；验收标准 D2/D3 按"待样例打分"处理。

## 6. 需要产品经理决定的问题

无。决策台账（D1–D10）中影响本阶段的待定项为零；D2/D3 的"待样例打分"在阶段 2 首次真实冒烟时处理，不影响技术适配。
