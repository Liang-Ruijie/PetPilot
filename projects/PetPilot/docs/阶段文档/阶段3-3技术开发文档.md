# 第 3-3 阶段开发文档（前端）｜聊天输入统一改版

> 配套：`docs/PRD/PetPilot-聊天输入交互改版说明.md`、`docs/阶段文档/前端适配声明.md`。
> 本阶段按改版说明重做聊天输入与照片交互；先跑通整体流程，复杂归属（分组归属）留后续迭代。

## 1. 本阶段目标

把打字、语音、拍照、选照片统一到聊天输入框；照片随消息发送、在聊天里查看；移除底部「照片」Tab；补上"正在思考…"与回到底部。

## 2. 范围

### 本阶段包含
- **统一输入框**：初始单行胶囊（左语音、中提示、右＋）；点文字展开成编辑区（上方文字、底部左语音、右＋和发送）；空草稿发送置灰；**语音为「按住说话」交互**（按住麦克风录音、松开转文字，沿用浏览器 Web Speech API；腾讯云 ASR 后续再接）；
- **照片进消息**：＋面板（拍照/照片）；最多 5 张；缩略图可横向滑动、每张可单独移除；超限提示；
- **消息发送**：一条消息 = 文字（描述）+ 照片；有图有字上照片下文字、纯图只照片、纯文字原气泡；刷新后仍在；
- **发送反馈**：点发送先显示用户消息 + "正在思考…"，返回后替换；失败可重试（复用原消息，不重复产生照片/记录）；
- **回到底部**：上翻历史时输入框上方显示"↓"，点它回最新；新回复到来不打断阅读；
- **照片归属**：文字明确提到猫名 → 文字+照片归该猫；无法确定 → 图文挂起 + 追问"这是哪只猫呀？"；事后"刚才那几张是明月的"→ 补归属到原消息照片；
- **分组归属**：同发多张时支持按张指定（如"前两张是明月，后三张是团团"→ 1-2 归明月、3-5 归团团；"这是明月和团团"→ 追问"哪几张是明月的？"）；
- **移除底部「照片」Tab**，照片统一走聊天输入；周回顾保留"照片 X 张"。

### 本阶段不包含
- 宠物档案入口（后期加 Tab/按钮/页面）；
- 云端 ASR（沿用浏览器语音）。

## 3. 用户流程

打开 → 点输入框 → 打字/点＋选照片或拍照 → （可选语音）→ 点发送 → 看"正在思考…"→ 收回复 → 归属不明确则追问 → 回答"是明月的"补归属。

## 4. 页面状态矩阵

| 状态 | 输入框 | 消息发送 |
| --- | --- | --- |
| 空 | 单行胶囊，发送隐藏 | — |
| 草稿 | 展开，发送点亮/置灰 | — |
| 提交中 | 禁用 | 用户消息 + 正在思考… |
| 成功 | 清空 | 回复替换思考 |
| 失败 | 保留草稿 | 失败提示 + 重试 |
| 待确认 | — | 图文挂起 + 追问 |

## 5. 接口契约

- `POST /api/messages` 改为 multipart：`text` + `files[]`（≤5 张）+ 可选 `description`；返回同现有结构，新增照片归属结果；
- 移除/保留 `POST /api/photos`：独立上传接口不再被前端使用，但保留兼容；
- 照片归属：`pet_id` 空 = 挂起；补归属复用确定性规则（"那几张是X/是X的"）。

## 6. 实现方案

- 前端：重构输入区为 `Composer` 组件（文字 + 缩略图 + 语音 + ＋面板 + 发送）；消息流加"正在思考…"占位与"↓"回底按钮；
- 后端：`POST /api/messages` 支持 multipart，照片存 `data/uploads/` 并关联 `message_id`；文字先走模型出 facts/提醒与 `photo_attributions`（照片序号区间→猫），按区间给照片归属；未明确的照片 `pet_id=NULL` 挂起；补归属/分组归属都通过确定性规则 + 模型区间输出落实；
- 移除底部导航「照片」Tab（前端）。

## 7. 验收标准

- 改版说明第五节 6 个场景全部走通（含分组归属、多组待确认）；
- 桌面 + 手机宽度正常；拍照/相册在手机可用（相机入口按设备支持，不支持则相册）；
- `verify.sh PetPilot 阶段3-3` 五项全过。

## 8. 风险与回退

- 相机入口依赖设备/浏览器，不支持时回退相册或提示；
- 分组归属依赖模型输出照片区间，模型不稳时回退为"无法唯一归属"挂起并追问，不误归；
- 照片进消息是前端+后端联调，出问题可回退到独立照片页（保留 `/api/photos` 兼容）。

## 9. 交付结果

- 统一聊天输入 + 照片进消息 + 移除照片 Tab + 思考/回底 + 照片归属/补归属；证据包（截图/照着做清单/是否表/verify 输出）。
