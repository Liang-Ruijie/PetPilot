# PetPilot 聊天输入交互改版说明

## 本次改动

1. 改造聊天输入框。主人在同一个对话里打字、说话、拍照、选照片，发送后直接在聊天里查看消息、收到回复并确认猫咪归属。
2. 移除底部导航的「照片」Tab 和独立照片页面。原先通过照片页完成的拍照、选图和填写描述，统一放到聊天输入流程。移除页面时保留已有照片及归属数据。

实现前先定位项目里现有的聊天输入、消息发送、语音转写、照片存储、归属追问、挂起和底部导航逻辑，优先复用。按钮配色、字号、圆角、间距、图标和移动端适配遵循 PetPilot 现有设计规范。改动范围限于上述两项。

## 一、输入框随操作变化

| 状态或操作 | 页面表现 |
|---|---|
| 初始状态 | 底部导航上方显示单行胶囊输入框。左侧是语音入口，中间提示「发消息或按住说话…」，右侧是「＋」。发送按钮隐藏。 |
| 点击文字区域 | 输入框向上展开成圆角编辑区。上方输入文字，底部左侧是语音入口，右侧依次是「＋」和发送按钮。空草稿的发送按钮置灰并禁用。 |
| 打字或添加照片 | 输入框中有非空白文字或至少一张照片，发送按钮即使用现有规范的主操作色并可点击。清空文字并移除所有照片后恢复禁用。 |
| 使用语音 | 沿用语音转文字流程。转写结果进入当前草稿，主人可以修改；点击发送后才提交。已选照片与确认后的文字一起发送。 |
| 点击「＋」 | 在聊天页打开操作面板，仅显示「拍照」「照片」。点「拍照」调用设备支持的拍摄入口，点「照片」调用系统图片选择器。关闭面板或取消选择后，保留已输入的文字和已选照片。 |
| 拍完或选完 | 回到展开的输入框。上方展示缩略图，每张右上角有独立的移除按钮；下方继续输入描述。保留先前写好的文字。此时属于草稿，主人点击发送才成为聊天消息。 |

## 二、每条消息最多 5 张照片

- 可以一次多选，也可以通过「＋」分次追加。拍照和相册选图合并计算，同一条消息共用一段可选描述。
- 缩略图按加入顺序从左到右排列，超出可视宽度时左右滑动。移除某张只影响该图，剩余照片保持顺序。
- 上限交互采用以下默认处理：已有 4 张又选 2 张时，保留原有 4 张，提示「这条消息还能加 1 张」，让主人重新选择；已有 5 张时提示「每条消息最多 5 张」。移除后可继续添加。避免悄悄丢弃超额图片。
- 发送成一条右侧用户消息。有图有字时上方展示照片、下方展示原文；纯图片消息只显示照片；纯文字消息沿用现有文字气泡。多图按发送顺序在同一组内左右滑动，只显示一次描述。用真实图片呈现内容，刷新后仍可在原消息位置查看。

## 三、发送反馈和回到底部

- 主人点击发送，在同一次界面更新中显示用户消息，并在它下面的助手回复位置显示「正在思考…」。纯文字、纯照片、图文、已确认的语音转写都走同一规则。等待上传或等待模型期间均有可见反馈。
- 第一段回复到达就用回复正文替换提示；若现有接口一次性返回，则在返回时替换。失败时结束等待提示，显示失败状态并允许重试；重试复用原消息，避免重复产生照片或记录。
- 主人正在看最新消息时，回复更新继续跟随到底部。向上翻看历史、离开底部时，在输入框上方水平居中显示圆形「↓」。新回复到来时保留当前阅读位置。点击「↓」回到最新消息并恢复跟随，到底后隐藏按钮。

## 四、统一对话里的猫咪归属

主人直接在统一聊天入口发送。发送前无需切换猫咪或填写归属。根据明确的猫名、指代和上下文判断；顶部可见的猫名、最近聊过的猫或照片外观，单独一项都不足以归属。

| 主人的表达或操作 | 助手与记录的行为 |
|---|---|
| 「明月今天拉稀了」，名字能唯一匹配 | 将这条记录及随附照片归到明月。上一句明确在说明月，紧接着发图说「这是它刚才的便便」，同样可沿用明确指代。 |
| 「小猫拉稀了」或只发图，无法确定是哪只猫 | 图文立即留在聊天里，归属沿用现有挂起机制。助手在原对话追问「这是哪只猫呀？」主人暂时没答时保留待确认状态。 |
| 后来回答「刚才那几张是明月的」，能唯一对应照片组 | 把归属补到原消息及对应照片上。保存成功后简短回复，如「收到，刚才这 3 张照片已经记到明月名下了。」数量使用实际张数。主人可以直接回答，无需引用或重新发图。 |
| 前后有两组待确认，回复无法指明是哪组 | 先问「你指的是前面那 3 张，还是后面那 2 张？」按实际情况区分。主人指明后，只更新对应组。 |
| 同发 5 张并说明「前两张是明月，后三张是团团」 | 聊天里保留一条消息和原有顺序。第 1–2 张归明月，第 3–5 张归团团。若只说「这是明月和团团」，追问「哪几张是明月的？」明确对应关系后再分别归属。 |

## 五、交付前走一遍的验收场景

1. **从空输入框开始。** 点击展开，输入空格时不能发送；输入文字后按钮点亮。通过语音生成文字，可先编辑再发送。
2. **从聊天完成选图。** 先写描述，再打开相册并取消，原文保留。再次选图，逐张移除、追加至 5 张，左右滑动可看到首尾两张。尝试超限时有提示。手机上分别走通拍照和相册入口。
3. **检查实际消息。** 分别发纯文字、纯照片、5 张图加一段描述。点击发送当下能看到消息和「正在思考…」。图文始终是一条消息；刷新后照片和文字仍对应，顺序正确。
4. **走通挂起和补归属。** 发 3 张未指明猫咪的照片，直接回答「是明月的」。核对原照片已关联明月、聊天只出现一次照片组。再用两组待确认照片检查歧义追问。
5. **测试同一消息含两只猫。** 发 5 张并说「这是明月和团团」，等助手追问后答「前两张明月，后三张团团」。核对每张归属，原图文仍在原位置。
6. **回看与导航。** 在助手回复时向上翻，阅读位置应稳定；点「↓」回到最新消息。检查底部已移除「照片」Tab，聊天里的「＋」可以独立完成传图全过程。
